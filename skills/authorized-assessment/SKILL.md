# 授权评估作业纪律

这个技能不教漏洞技巧，只规定**这个控制台该怎么被用**。任务引擎是确定性的、会真的发请求，
所以纪律必须写在流程最前面。

## 1. 开工前（缺一不可）

- 拿到**书面授权**：目标清单（域名/IP/端口）、时间窗、可接受的影响等级、应急联系人。
- 明确**不可碰**的部分：支付/结算、生产数据库、第三方托管在目标域名下的系统。
- 记录授权来源（合同号/工单号）与联系人的一句话结论，写进任务名的括注里，例如：
  `官网门户 授权评估（工单 SEC-2026-0412）`。
- 确认出口 IP 已向对方报备，避免被当成攻击流量封禁或误报。

## 2. 只读优先

| 动作 | 默认 | 说明 |
| --- | --- | --- |
| GET 首页 / robots / security.txt | 允许 | 引擎默认行为 |
| 读响应头、TLS 证书 | 允许 | 不产生副作用 |
| `/​.git/config`、`/.env` 等暴露点 | 允许（只读一次） | 命中即停，不下载整库 |
| 目录爆破、口令猜测 | **禁止** | 需要单独立项与对方确认 |
| 上传/写入/删除类接口 | **禁止** | 即使"看起来无害" |
| 压力/并发测试 | **禁止** | 不属于本工具范围 |

一条经验：命中敏感文件时**只取能证明结论的最小片段**写进证据，不要把凭据全文抄进报告。

## 3. 证据

- 每条发现必须有：位置、判定依据（响应头/正文片段/证书字段）、时间。
- 控制台的「流量」页是底稿，「漏洞」页是结论；报告只引用这两处的原文。
- 拿不到证据的判断写成"疑似"并说明原因，不要凑等级。

## 4. 移动端（安卓模式）

- 只对接入**你自己的**测试机或对方提供的测试机；令牌按口令管理，用完即删。
- 设备命令会真的执行：`rm`、`pm uninstall`、`settings put` 这类动作先想清楚再敲。
- APK 静态结论只覆盖清单与 dex 字符串；加固包要注明"壳未还原，结论仅限外层"。
- 抓包涉及的流量属于对方数据，pcap 用完按约定删除或移交，不要留在本机 `data/artifacts/`。

## 5. 收口

1. 每条未关闭发现过一遍：证据是否成立、是否重复、是否属于本次范围。
2. 生成报告 → 复核等级与措辞 → 交付。
3. 清理：删除令牌、关闭反推监听、清掉临时产物。
4. 把本次的新套路写回技能库（`skills/<名字>/SKILL.md`），下次直接复用。
